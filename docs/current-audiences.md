# Current audiences and retained attendance

Twinevia separates today's messaging audience from the records needed for attendance, feedback and support. Automatic expiry changes the view and audience totals; it does not delete event registrations, community contacts, STOP evidence, replies, surveys or message history.

The event list defaults to **Current events**. Future and ongoing events remain visible. A known source end timestamp expires at that instant; date-only events remain current through the event day in the configured application timezone. Undated events stay current until their date is known. Source events marked deleted, canceled, draft or private are outside the current view. The same tenant-scoped predicate supplies dashboard selectors and current RSVP totals, so an event automatically leaves the current audience without waiting for a cleanup job or WordPress reconciliation. The current implementation previously had no attendee-expiry job: WordPress reconciled future events while Twinevia continued counting every retained registration.

**Past events** retains attendance and feedback context. Its event detail labels eligible follow-up contacts separately and offers **Send follow-up / feedback**, which opens the existing composer with that exact event selected. Current events remain the default choices; an explicitly selected historical event is included for the requested follow-up. Passing an event date does not withdraw consent or invalidate a previously frozen manual follow-up. Manual immediate and scheduled follow-ups continue to check actual opt-outs, suppression, tenant and existing permission rules at execution. No new consent purpose or AOC reapproval is required.

Only proven provider-synced pre-event reminder kinds (`two_week`, `seven_day`, `one_day`, `day_of`) expire when their retained event has ended or become inactive. The source, encoded automation key and exact local event identity must match. The scheduler checks before provider construction; dispatch checks again while holding the schedule lock immediately before each actual submission. If the event ends between recipients, earlier accepted SIDs remain accepted and the remaining recipients are not submitted. Manual follow-ups, feedback and other automation kinds do not acquire this expiry gate.

The community list defaults to **Contactable**. Tenant-bound SQL excludes actual unsubscribe and suppression entries, plus the latest transport-wide denial, before search pagination and totals. Existing historical phone formatting is normalized for negative-list matching. The default CSV uses the same view. **All contacts** and its CSV retain the records and status needed for review; displaying a blocked contact there never authorizes a send. The filter does not invent missing permission or require existing AOC signups to be approved again. The established AOC community signup contract remains in effect, with explicit refusals taking precedence.

Dashboard totals use contactable community entries and current contactable RSVPs. The overall contact total counts unique phones across the two audiences, so a person who is both a community member and an event attendee is counted once. A past attendee can remain an eligible community member under the organization's signup contract while leaving the current event RSVP total.

Focused tests cover90 retained past attendees with a zero current RSVP count, future/multiday/DST/date-only expiry, blocked rows before pagination, formatted historical restrictions, cross-tenant isolation, transport STOP/START ordering, current unique counts, explicit past-event review and actual mocked-provider sends, frozen scheduled feedback with STOP rechecking, and an event ending between submissions. Browser checks exercise desktop and390px mobile list filters, keyboard navigation, history-to-feedback composition, review and opt-out retention. Providers are mocked/faked and local test databases are disposable; these tests do not send real messages or change customer data.
